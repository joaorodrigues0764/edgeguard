# Smoke test: Workers AI through AI Gateway

This opt-in test makes one real inference for a synthetic checkout spike. The twentieth request returns HTTP 503 in 6,100 ms and opens the episode with 13 failures in 20 requests. D1, the queue and the dashboard run locally; no Worker is deployed. Inference uses the selected Cloudflare account's Workers AI allowance or billing.

1. Use an account where you can run Workers AI, use AI Gateway and start Wrangler remote binding sessions. Run `npx wrangler login` in your terminal, approve the browser prompt and use `npx wrangler whoami` to verify the account. If you have multiple accounts, set `CLOUDFLARE_ACCOUNT_ID` locally to the intended account ID. No provider API key belongs in the project.
2. Use the account's **default** AI Gateway. Cloudflare can create it on the first authenticated request. To use a dedicated gateway, create it in **AI Gateway**, copy its gateway ID (slug), and set `AI_GATEWAY_ID` in your shell. Ensure that the account can run `@cf/meta/llama-3.3-70b-instruct-fp8-fast` and that gateway policies allow it. The binding supplies authentication.
3. From the repository root, install the locked dependencies with `npm ci` and run `python3 demo/run.py --live`. Use Python 3 and a Node.js version supported by the installed Wrangler (verified with Node 26). The launcher migrates a new temporary local database, seeds the first 19 checkout requests, starts Wrangler with a remote AI binding and submits the threshold-crossing request through the ingestion API. It prints a local dashboard address on port 8793 and a temporary dashboard password.
4. Sign in there. Refresh after queue processing and select **GET /synthetic/checkout**. Expect an **open**, **critical** incident, the deterministic rule, **Complete**, an English summary, possible causes labelled as hypotheses and suggested next steps. Wording varies. The model receives the synthetic endpoint and its opening window evidence. Expect the summary to describe 13 HTTP 5xx responses in 20 requests (65%) and mean latency of 6,100 ms. Gateway payload logging is disabled for this request.
5. If analysis shows **Failed**, the incident should still be present. Check account selection, model availability, allowance and gateway policies. Choose **Retry analysis** after correcting the problem; refresh to inspect the same incident. A retry in this mode can make another billable call. Stop with Ctrl+C to remove temporary local data. No account resources are deleted.

See Cloudflare's [Workers AI binding and gateway setup](https://developers.cloudflare.com/ai-gateway/integrations/aig-workers-ai-binding/) and [JSON Mode schema and supported models](https://developers.cloudflare.com/workers-ai/features/json-mode/).
